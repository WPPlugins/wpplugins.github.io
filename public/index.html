    Developer Guide: Git & Submodules for WordPress

    1. Adding Plugins as Git Submodules

    Using Git submodules keeps your WordPress project repository clean while tracking exact plugin versions: 

    # From your WordPress project root:
git submodule add https://github.com/WPPlugins/<slug>.git wp-content/plugins/<slug>
git commit -m "chore: add <slug> plugin submodule"

    2. Cloning a Project That Uses Submodules

    git clone --recurse-submodules <your-project-repo-url>
# Or, if already cloned:
git submodule update --init --recursive

    3. Updating a Submodule to Latest trunk or a Specific Tag

    # Track latest trunk (main):
git submodule update --remote wp-content/plugins/<slug>

# Or pin to a specific WordPress.org release tag:
cd wp-content/plugins/<slug>
git fetch --tags
git checkout 1.2.3
cd ../../..
git add wp-content/plugins/<slug>
git commit -m "chore: bump <slug> to 1.2.3"

    4. Using with Composer

    You can add any mirror as a VCS repository in composer.json (note: most WordPress.org plugins do not ship their own composer.json, so use type: package if needed, or pair with WPackagist).

    Mirrors are read-only and updated automatically by WPPlugins/mirror-orchestrator. Index refreshes every 2 hours.
